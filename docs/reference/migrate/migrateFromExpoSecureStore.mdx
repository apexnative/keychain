expo-secure-store keeps its items where this package doesn't look: Keychain items of its own on iOS, its own preferences and Keystore keys on Android. This function reads them, writes each under the same key into a storage of this package, and reports what it did.

## Usage {#usage}

```ts title="src/storage/migrate.ts"
import { migrateFromExpoSecureStore } from '@apexnative/keychain/migrate';

const report = await migrateFromExpoSecureStore({ removeSource: true });
// { migrated: ['accessToken', 'refreshToken'], skipped: [], warnings: [] }
```

`SecureStore.getItemAsync('accessToken')` becomes `keychain.getItem('accessToken')`.

### Returns {#returns}

A [MigrationReport](./types#migrationreport). Its keys are the items' keys.

## Notes {#notes}

- **Several `keychainService` values become one storage.** Items of different services go to the same `into` under their keys; when two services have the same key, the second is skipped as `exists`. Move each service into a storage of its own when that matters:

  ```ts
  import { createKeychain } from '@apexnative/keychain';

  await migrateFromExpoSecureStore({ keychainService: 'auth', into: createKeychain({ service: 'auth' }) });
  ```

- **Protected items** (`requireAuthentication: true`) are skipped as `requiresAuth`: reading them needs the prompt. Move them with [`migrateItem`](./migrateItem).
- **Nothing is overwritten**: a key that is taken in `into` is skipped as `exists`.
- **Run it before expo-secure-store is used** in this launch, or after it is removed, when `removeSource` is `true`: two libraries shouldn't work on the same items at once.
