The package can't see react-native-keychain's items: on iOS it reads only its own Keychain items, and on Android rnk keeps its data in files and keys of its own. This function reads them where rnk left them, writes each into this package, and reports what it did. Run it once at startup, before the code that reads the secrets.

## Usage {#usage}

```ts title="src/storage/migrate.ts"
import { migrateFromReactNativeKeychain } from '@apexnative/keychain/migrate';

export async function migrateSecrets() {
  await migrateFromReactNativeKeychain({ removeSource: true }); // rnk's default service

  const report = await migrateFromReactNativeKeychain({
    services: ['auth'], // the `service` values your app passed to rnk
    servers: ['api.example.com'], // the servers of setInternetCredentials
    removeSource: true,
  });
  // {
  //   migrated: ['auth'],
  //   skipped: [{ key: 'api.example.com', kind: 'internetPassword', reason: 'requiresAuth' }],
  //   warnings: [],
  // }
  return report;
}
```

A second run finds nothing new: what was moved is either gone (`removeSource: true`) or marked as moved, and nothing is written twice.

### Returns {#returns}

A [MigrationReport](./types#migrationreport): the keys moved, the items skipped with a reason, and the warnings about old items that stayed.

## Where each item goes {#where}

| rnk item | Becomes | Key in the report |
| --- | --- | --- |
| A generic password of service `S` (`setGenericPassword(u, p, { service: S })`) | The credentials of the storage `createKeychain({ service: S })`: `getCredentials()` there gives `{ username: u, password: p }` | `S` |
| rnk's default service | The credentials of the default storage, [`keychain`](/api/storage/keychain) | The service |
| Internet credentials of server `X` | The credentials of `into` with `server: X`: `into.getCredentials({ server: X })` | `X` |

The username is kept with the password in one item. The same layout is what [`/compat`](/api/compat/overview) reads and writes, so an app can move the data and keep rnk's calls for a while.

The new items are written with the defaults of their storage: `afterFirstUnlock`, no access control. A protected rnk item isn't moved here at all.

## What is skipped {#skipped}

- **`requiresAuth`** — the rnk item needs the user (rnk's `accessControl`). This function never shows a prompt; move it with [`migrateItem`](./migrateItem) when the user is there, such as on the sign-in screen.
- **`exists`** — this package has an item under the key already: nothing is overwritten. Also an item that an earlier run moved and kept.
- **`notFound`** — the item vanished between the listing and the read, or has no value.
- **`error`** — reading or writing failed; `error` holds the `KeychainError`.

## Running it safely {#safely}

- **Only once react-native-keychain is out of the way.** With `removeSource: true`, run the migration before the app's code calls react-native-keychain in this launch, or once rnk is removed from the app. Otherwise both libraries work on the same items at once.
- **One run at a time.** The items are moved one after another; don't start a second migration while one runs.
- **No item is lost.** The old item is deleted, or marked, only after the new one is written. When that last step fails, the new item is there and the report has a warning; the next run skips the item as `exists`.
