Every method of the package fails with a `KeychainError`: an async one rejects with it, a sync one throws it. Whatever the native side reports, an `OSStatus`, an `LAError` or a `BiometricPrompt` code, comes to JavaScript as one of the [codes](./KeychainErrorCode), so one `switch` handles both platforms. A missing item is not an error: it is `null`.

## Usage {#usage}

```ts
import { KeychainError, KeychainErrorCode } from '@apexnative/keychain';

try {
  return await vault.getItem('refreshToken');
} catch (error) {
  if (!(error instanceof KeychainError)) throw error;
  switch (error.code) {
    case KeychainErrorCode.UserCanceled:
      return showPasswordForm();
    case KeychainErrorCode.KeyInvalidated:
      return signInAgain();
    default:
      log(error.code, error.nativeCode, error.nativeDomain, error.message);
      throw error;
  }
}
```

The package makes its errors itself; an app makes one in tests and in its own wrappers, to fail the way the package does:

```ts
import { KeychainError, KeychainErrorCode } from '@apexnative/keychain';

const canceled = new KeychainError(KeychainErrorCode.UserCanceled, 'The user canceled the prompt.');
```

## What becomes a KeychainError {#mapping}

- **A check in JavaScript** — a key, a value or an option that isn't valid — is `INVALID_ARGUMENT`, thrown before the native call.
- **A native failure** comes with its code. A code the package doesn't know becomes `UNKNOWN`, with the native code and domain kept.
- **No native module** — Expo Go, the web, an app not rebuilt after the install — is `UNSUPPORTED`, with a message that says how to fix it.

[Error codes](/docs/help/error-codes) has every code: when it happens, the native error behind it, and what to do.
