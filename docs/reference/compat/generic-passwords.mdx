A generic password is a user name and a password under a service. Here it is the [credentials](/api/storage/methods#setCredentials) of the store of that service: the password is the secret, and the user name is kept with it, and `getCredentials` returns both. Without a `service`, the store is the default one, [`keychain`](/api/storage/keychain).

## Usage {#usage}

```ts title="src/auth/session.ts"
import * as Keychain from '@apexnative/keychain/compat';

export async function saveSession(username: string, refreshToken: string) {
  await Keychain.setGenericPassword(username, refreshToken, {
    service: 'auth',
    accessControl: Keychain.ACCESS_CONTROL.BIOMETRY_CURRENT_SET,
    accessible: Keychain.ACCESSIBLE.WHEN_UNLOCKED_THIS_DEVICE_ONLY,
  });
}

export async function restoreSession() {
  if (!(await Keychain.hasGenericPassword({ service: 'auth' }))) return null; // no prompt
  const credentials = await Keychain.getGenericPassword({
    service: 'auth',
    authenticationPrompt: { title: 'Sign in to Example', cancel: 'Use password' },
  });
  return credentials ? credentials.password : null;
}

export async function signOut() {
  await Keychain.resetGenericPassword({ service: 'auth' });
}
```

## setGenericPassword {#setGenericPassword}

```ts
function setGenericPassword(
  username: string,
  password: string,
  options?: SetOptions
): Promise<Result>;
```

<Facts returns="Promise<Result>" prompt="Never: a write shows no prompt, whatever its `accessControl`" throws="`INVALID_ARGUMENT`, `UNSUPPORTED`, `HARDWARE_UNAVAILABLE`, and what the device can't do: `BIOMETRY_NOT_ENROLLED`, `PASSCODE_NOT_SET`, …" />

Writes the user name and the password of the service, in place of what was there. It calls [`setCredentials`](/api/storage/methods#setCredentials) in the store of `service`, and adds the service to the list of [`getAllGenericPasswordServices`](#getAllGenericPasswordServices) unless it is the default one.

<Params
  items={[
    { name: 'username', type: 'string', required: true, text: 'Kept with the password in the item. Not empty, without U+0000.' },
    { name: 'password', type: 'string', required: true, text: 'The secret. Any string without U+0000; for binary data use the core\'s `setBytes`.' },
    { name: 'options', type: 'SetOptions', text: 'Which service, and how to protect the item. See [SetOptions](./types#setoptions).' },
  ]}
/>

| Option | Here |
| --- | --- |
| `service` | The store of that service; without it, the default store |
| `accessible` | [`ACCESSIBLE`](./constants#accessible), mapped to the core's [`Accessible`](/api/options/Accessible); `ALWAYS` is `UNSUPPORTED` |
| `accessControl` | [`ACCESS_CONTROL`](./constants#access-control), mapped to the core's [`AccessControl`](/api/options/AccessControl); `APPLICATION_PASSWORD` is `UNSUPPORTED` |
| `cloudSync` | iOS: `synchronizable`, the item goes to iCloud Keychain |
| `accessGroup` | iOS: the access group of the store |
| `securityLevel` | Android: `SECURE_HARDWARE` fails with `HARDWARE_UNAVAILABLE` on a device that keeps keys in software; `ANY` and `SECURE_SOFTWARE` change nothing |
| `storage` | `UNSUPPORTED`, any value |
| `authenticationPrompt` | Ignored: a write shows no prompt |

It resolves with the service and the storage, as rnk does: `{ service, storage }`, where `storage` is `'keychain'` on iOS and `'KeystoreAESGCM'` on Android.

```ts
await Keychain.setGenericPassword('ivan', 'secret');
// { service: 'com.example.app', storage: 'keychain' }
```

The core's checks apply: an empty user name, U+0000 in a string, an empty `service`, or `cloudSync` with an `accessControl` is `INVALID_ARGUMENT`. See [Options and checks](./overview#options).

## getGenericPassword {#getGenericPassword}

```ts
function getGenericPassword(options?: GetOptions): Promise<UserCredentials | false>;
```

<Facts returns="Promise<UserCredentials | false>" prompt="When the item was written with an `accessControl`" throws="What the prompt ends with: `USER_CANCELED`, `LOCKOUT`, `KEY_INVALIDATED`, …; `UNSUPPORTED` for `APPLICATION_PASSWORD`" />

Reads the user name and the password of the service, or `false` when there are none. It calls [`getCredentials`](/api/storage/methods#getCredentials) in the store of `service`.

<Params
  items={[
    { name: 'options', type: 'GetOptions', text: 'Which service, and the texts of the prompt. See [GetOptions](./types#getoptions).' },
  ]}
/>

```ts
const credentials = await Keychain.getGenericPassword({ authenticationPrompt: 'Unlock your account' });
// { service: 'com.example.app', username: 'ivan', password: 'secret', storage: 'keychain' } or false
```

- `authenticationPrompt` as a string is the title. As an object it takes `title`, `subtitle`, `description` (Android) and `cancel`. Without it, the prompt has rnk's texts: `Authenticate to retrieve secret` and `Cancel`.
- The `accessControl` of the options is checked and then ignored: the item keeps the protection it was written with. `authenticationType` is ignored too.
- A prompt that doesn't end in success rejects with a `KeychainError` and its code: `USER_CANCELED`, `LOCKOUT`, `KEY_INVALIDATED`. See [Errors](./overview#errors).

## hasGenericPassword {#hasGenericPassword}

```ts
function hasGenericPassword(options?: BaseOptions): Promise<boolean>;
```

<Facts returns="Promise<boolean>" prompt="Never" />

Whether the service has a generic password. It calls [`hasItem('credentials')`](/api/storage/methods#hasItem) in the store of `service`, so a protected item is found without a prompt.

```ts
if (await Keychain.hasGenericPassword({ service: 'auth' })) showFaceIdButton();
```

## resetGenericPassword {#resetGenericPassword}

```ts
function resetGenericPassword(options?: BaseOptions): Promise<boolean>;
```

<Facts returns="Promise<boolean>" prompt="Never" />

Deletes the generic password of the service and takes the service off the list of [`getAllGenericPasswordServices`](#getAllGenericPasswordServices). It calls [`removeCredentials`](/api/storage/methods#removeCredentials) in the store of `service`. It resolves `true`, also when there was nothing to delete; the other items of the store stay.

```ts
await Keychain.resetGenericPassword({ service: 'auth' }); // true
```

## getAllGenericPasswordServices {#getAllGenericPasswordServices}

```ts
function getAllGenericPasswordServices(options?: GetAllOptions): Promise<string[]>;
```

<Facts returns="Promise<string[]>" prompt="Never" />

The services that have a generic password now: the app's default service first, when the default store has credentials, then the others, sorted.

```ts
await Keychain.setGenericPassword('a', '1');
await Keychain.setGenericPassword('b', '2', { service: 'work' });
await Keychain.getAllGenericPasswordServices(); // ['com.example.app', 'work']
```

The package can't list every store on the device, so the other services come from a list it keeps: the item `generic-services` in the store `apexnative.keychain.compat`. `setGenericPassword` and the [migration](/api/migrate/migrateFromReactNativeKeychain) add a service to it; `resetGenericPassword` removes it. A service on the list is answered only while its credentials are still there, so credentials removed through the core API drop out too.

What this list can't know:

- A store whose credentials were written by the core's `setCredentials`, not through the layer or the migration, is not listed, except the default one.
- rnk's own items aren't listed before they are migrated: the layer reads only this package's items.

`skipUIAuth` is accepted and changes nothing: listing never shows a prompt.
