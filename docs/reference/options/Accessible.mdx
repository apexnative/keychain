`Accessible` is the value of the [`accessible`](./KeychainOptions#accessible) option, and what [`getItemInfo`](/api/storage/methods#getItemInfo) reports. It is a plain object of strings with a type of the same name, not a TypeScript `enum`: `Accessible.WhenUnlocked` is the string `'whenUnlocked'`, and both forms are accepted.

## Usage {#usage}

```ts
import { Accessible, keychain } from '@apexnative/keychain';

await keychain.setItem('refreshToken', token, { accessible: Accessible.WhenUnlockedThisDeviceOnly });
await keychain.setItem('refreshToken', token, { accessible: 'whenUnlockedThisDeviceOnly' }); // the same
```

## Signature {#signature}

```ts
const Accessible: {
  readonly AfterFirstUnlock: 'afterFirstUnlock';
  readonly AfterFirstUnlockThisDeviceOnly: 'afterFirstUnlockThisDeviceOnly';
  readonly WhenUnlocked: 'whenUnlocked';
  readonly WhenUnlockedThisDeviceOnly: 'whenUnlockedThisDeviceOnly';
  readonly WhenPasscodeSetThisDeviceOnly: 'whenPasscodeSetThisDeviceOnly';
};

type Accessible = (typeof Accessible)[keyof typeof Accessible];
```

## Values {#values}

| Constant | String | Readable | On Android |
| --- | --- | --- | --- |
| `AfterFirstUnlock` | `'afterFirstUnlock'` | From the first unlock after a restart until the next restart, in the background too. The default | A Keystore key without a lock requirement; an app without direct boot doesn't run before the first unlock |
| `AfterFirstUnlockThisDeviceOnly` | `'afterFirstUnlockThisDeviceOnly'` | The same, and the item stays on this device | The same as `afterFirstUnlock` |
| `WhenUnlocked` | `'whenUnlocked'` | Only while the device is unlocked | A key with `setUnlockedDeviceRequired(true)` on Android 9+; before, the package checks the lock itself |
| `WhenUnlockedThisDeviceOnly` | `'whenUnlockedThisDeviceOnly'` | The same, and the item stays on this device | The same as `whenUnlocked` |
| `WhenPasscodeSetThisDeviceOnly` | `'whenPasscodeSetThisDeviceOnly'` | Only while the device is unlocked and has a passcode. Removing the passcode makes the item unreadable | The write needs a secure device (`PASSCODE_NOT_SET` without one) |

On iOS each value is the `kSecAttrAccessible…` constant of the same name.

- **This device only.** The `…ThisDeviceOnly` values keep an item out of iCloud Keychain and out of an encrypted iOS backup restored on another device. On Android every item is this-device-only: Keystore keys never leave the device. An item with `synchronizable: true` can't have one of them (`INVALID_ARGUMENT`).
- **A locked device.** A read or a write at a time the value doesn't allow fails with `INTERACTION_NOT_ALLOWED`. With `afterFirstUnlock`, background work such as a silent push or a background fetch can read the item once the phone has been unlocked after a restart; that is why it is the default.
- **Not here.** iOS's `kSecAttrAccessibleAlways` is deprecated by Apple and has no value.
